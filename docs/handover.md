# 引き継ぎメモ

## はじめに

このリポジトリは **JK-Cafeの2026年保存版** です。元のパンケーキの見た目や当日の注文体験を残すため、ここで無理に汎用化しないことをおすすめします。別の屋台向けの改善はForkまたは別リポジトリで進めてください。

## 構成

- `src/customer.tsx`：お客さん側の受付画面
- `src/order-wizard.tsx`：商品とトッピングのステップ式選択
- `src/pancake-preview.tsx`：食品素材の合成表示
- `src/staff.tsx`：スタッフ/キッチン/管理側
- `src/shared.tsx`：共通UI・モデル
- `server/index.js`：HTTP/API/Socket.IOの入口
- `server/store.js`：会計・在庫・注文の一貫性を担保する中心処理
- `server/migrate.js`：商品初期登録/DBマイグレーション
- `server/auth.js`：管理PIN/端末登録
- `test/`：注文・在庫・返金・権限・描画などの自動テスト

## 汎用版にするときの優先順

1. **保存版をタグ付きで保全**：元のリポジトリを残し、別リポジトリで汎用版を開始。
2. **商品データを外出し**：`server/migrate.js` の初期パンケーキ設定を設定ファイル化。
3. **注文ルールを設定化**：必須のソース1種、無料トッピング1種、スペシャル固定構成、クーポン30円引きを商品/店舗設定へ移す。
4. **任意の選択グループへ**：`src/shared.tsx` の` syrupId`、`includedId`のようなパンケーキ固有の項目を、複数の選択項目を保存できるモデルへ移行。
5. **注文ウィザード生成**：`src/order-wizard.tsx` の固定5ステップを、商品設定から生成する。
6. **プレビューを差し替え可能に**：現在のパンケーキ画像合成を専用部品として残し、ほかの店舗には写真表示を提供。
7. **DB互換性テスト**：古い注文の価格と構成が、メニュー変更後も変わらないことを保証。
8. **設定画面**：設定ファイルによる汎用化が安定してから、ノーコードの管理UIを追加。

## 大切な注意

**価格・在庫・割引はサーバー側で検証・計算する**こと。入金の二重実行防止、通信失敗後の受付確認、トランザクション、競合検知、返金・訂正・締めの整合性は優先して引き継ぐこと。
