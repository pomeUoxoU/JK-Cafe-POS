# よくあるトラブル（Windows）

## `Cannot find package 'express'` / `ERR_MODULE_NOT_FOUND`

`node_modules` が未インストールです。**`setup.cmd` をダブルクリック**してください。`npm ci` で必要な依存パッケージを導入し、`npm run build` で画面を作ります。`start.cmd` も不足を検知した場合はセットアップを試みます。

## `node` や `npm` が見つからない

Node.js 22.16以降（npm同梱）をインストールして、フォルダを開き直してから `setup.cmd` を再実行してください。インストール済みの場合は、コマンドプロンプトで `node -v` と `npm -v` が表示されるか確認してください。

## `npm ci` に失敗する

初回セットアップにはインターネット接続が必要です。接続を確認した上で再実行。失敗する場合はコマンドプロンプトでこのプロジェクトのフォルダを開いて `npm ci` を実行し、表示されたエラーを確認してください。

**注意**：解決のために `package-lock.json` を無闇に削除したり、別のZIPに含まれる `node_modules/` を丸ごとコピーすることは推奨しません。

## `npm run build` に失敗する

`setup.cmd` に表示されたエラーを確認してください。`node_modules` の破損が疑われる場合は `setup.cmd` をもう一度実行すると `npm ci` が依存パッケージを再構築します。

## サーバーは起動したがブラウザが見られない

PCから `http://localhost:3000/` を開いてください。他の端末では、**同じWi-Fi**に接続し、PCのLAN内IPを使った `http://<PCのLAN内IP>:3000/` にアクセスします。Windowsファイアウォールで、信頼できるプライベートネットワーク上のTCP 3000が許可されているか確認します。ルーターのインターネット向けポート開放はしないでください。

## すぐ閉じる／動かない

`start.cmd` は正常な終了・異常終了いずれもログを残して一時停止する構成です。**表示されたエラーをコピーまたはスクリーンショット**して確認してください。初回セットアップ後は `data/` に運用DBや管理PINが作成されるため、サポートを受ける際もこのフォルダは共有しないでください。

## 管理PINはどこ？

初回起動時に `data/initial-access.json` に作成されます。**公開・アップロード・SNS掲載はしないでください。**

## テストしたい

コマンドプロンプトで `npm test` を実行してください。本配布ZIP内のWindows用スクリプトは、配布環境でのダブルクリック実機テストは未実施です。屋台本番前の運用テストは必須です。
