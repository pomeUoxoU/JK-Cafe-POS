# 当日運用ガイド

## 画面の使い分け

| 担当 | パス | 操作 |
| --- | --- | --- |
| お客さん | `/` | 商品・ソース・基本/追加トッピング・クーポン選択、注文送信 |
| 会計 | `/staff` | 受付番号確認、現金を預かる、入金処理、お釣り案内 |
| 調理 | `/kitchen` | 入金済み注文の確認、調理着手、完成、受け渡し |
| 管理 | `/admin` | 在庫/価格/販売状態、精算・締め、端末設定など |

**注文が送信された段階では売上ではありません。会計スタッフによる入金後に売上として計上され、調理へ連携されます。**

## 開店前

1. PCを電源につなぎ、睡眠・自動更新・Wi-Fi切断が起きないよう確認。
2. ローカルネットワークを接続。端末登録と通知音をテスト。
3. すべての商品と追加トッピングの価格、販売状態、在庫を管理画面で確認。
4. 現金の釣り銭準備。クーポン適用額と受付担当のルールを統一。
5. 1件のテスト注文を完了させ、削除/返金/記録の扱いを確認して本番を開始。

## トラブル時

- **注文画面がつながらない**：PCサーバー稼働、Wi-Fi、LAN内IP、端末間通信を確認。
- **注文が二重になったか不明**：お客さん画面の受付結果確認を優先し、むやみに再送しない。
- **売り切れ**：管理画面で在庫や販売状態を調整。材料がなくなったら注文を止めてから発注/補充。
- **会計や返金の誤り**：レジ側の訂正/取消・返金手順を使用し、会計台帳と現金を照合。
- **端末紛失・転用**：管理画面から登録を失効させる。

## 閉店時

未会計注文、未提供注文、返金履歴を確認し、日次売上/CSV/締め処理を実施。`npm run backup` でDBを保全。バックアップファイルには認証情報が含まれるため、**外部公開しないこと**。
